# 前端页面设计规范

> 状态：`F0 INFORMATION ARCHITECTURE CONFIRMED / VISUAL REVIEW OPEN`
>
> 更新时间：2026-09-01
>
> 适用范围：`admin-web`、`employee-web`、`employee-miniapp`
>
> 说明：本文件已根据用户确认形成页面信息架构与角色权限基线；视觉方案仍待评审和美化，不把尚未完成的 API、真实微信接入或前端工程代码描述为已实现。

## 1. 设计定位

产品服务的是机场保障现场，不是泛企业 BI。页面要让人快速回答“哪一班航班、哪一项任务、谁来处理、现在能不能操作、操作是否已确认”。

设计主题定为“蓝调停机坪 / Blue-hour apron”：

- 管理端像一张安静、持续更新的运行台，信息密度高但不嘈杂；
- 员工端像一张随身携带的任务卡，进入后直接看到当前任务和下一步动作；
- 黄色只代表需要注意或可以执行的信号，红色只代表阻断或危险，不把颜色当作唯一状态信息；
- 视觉重点放在航班、时间、任务状态和同步反馈，不使用视频背景、粒子、玻璃拟态或大面积渐变。

### 1.1 本轮重开原因

当前页面稿已完成信息架构方向确认，进入正式前端工程前仍需评审：

- 管理端、员工端、登录页必须是独立页面/独立客户端路由，不在一个预览壳里模拟正式产品结构；
- 任务可见性必须服从角色与管辖范围：队长只能看到自己管辖的任务，主任可以查看全部任务；当前已确认角色映射，团队/区域 Scope 交叉与后端字段仍需落成最终合同；
- 管理端左侧工作区不能只有任务工作台，需要根据项目文档补齐航班、任务、人员/岗位/能力、规则、事件/通知、审计/报表和系统设置等实际模块；当前已确认首期保留完整导航，模块内容可后续接入；
- 当前“蓝调停机坪”视觉方案和预览细节需要继续美化，最终视觉稿在讨论完成前不冻结。

### 1.2 记忆点：航班条带与状态轨

每个任务都使用一条简短的“航班条带”：左侧是计划时间和航班显示号，中间是任务名称与区域，右侧是业务状态；卡片或详情页边缘用一条 4px 状态轨标出当前状态。状态轨必须同时配合文字和图标。

```text
07:40  MU 2156  ──  客舱清洁        T2 / A区        待接受
      └────────────── 状态轨：amber ─────────────────┘
```

这条状态轨是唯一的视觉冒险点：它来源于停机坪作业条和航班时刻条的组合，服务于扫描和状态识别，不承担动画装饰。

## 2. 视觉基线

### 2.1 色彩 Token

| Token | 色值 | 用途 |
|---|---|---|
| `ink-900` | `#102431` | 主文字、管理端深色导航、深色表面 |
| `paper-050` | `#F5F7F6` | 全局浅色背景，避免纯白刺眼 |
| `line-200` | `#D7E1E4` | 分割线、输入框边界、卡片边界 |
| `signal-amber` | `#F2B544` | 待处理、可执行主动作、当前关注项 |
| `signal-teal` | `#16847A` | 已同步、已完成、稳定成功 |
| `signal-red` | `#C94B45` | 失败、阻断、不可执行 |

补充规则：

- `signal-amber` 上使用 `ink-900` 文字，保证按钮和标签的对比度；
- `signal-teal`、`signal-red` 不单独作为浅色背景，优先使用浅色底 + 深色文字 + 图标；
- 信息提示使用 `#2D6E9F`，仅用于辅助信息，不与业务成功混用；
- 深色导航只能出现在管理端外壳和必要的重点标题区，员工端不使用全屏深色界面；
- 颜色 Token 集中放在 `packages/ui`，小程序和 Web 可以共享语义，不强求共享 CSS 实现。

### 2.2 字体与数字

- 正文：`"Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`；
- 英文和数字：`Inter`, `"DIN Alternate"`, `"Arial Narrow", sans-serif`；
- 时间、航班号、Task ID 使用 `font-variant-numeric: tabular-nums`，让列表纵向扫描时数字不跳动；
- 页面标题最多两级，管理端标题 24/32px，员工端标题 20/28px；不使用超大营销式数字；
- 字重只使用 400、500、600，避免小屏幕上过度加粗。

### 2.3 空间、圆角与表面

- 基础间距 4px，页面常用间距为 8、12、16、24、32px；
- 管理端卡片圆角 10px，员工端任务卡片圆角 14px，按钮圆角 9px；不使用胶囊化所有元素；
- 边界优先使用 1px `line-200`，阴影仅用于弹层和底部操作区：`0 8px 24px rgba(16,36,49,.10)`；
- 员工端使用浅色背景和白色卡片形成层次，管理端使用浅灰工作区 + 白色内容面板；
- 不用 `backdrop-filter`、大面积 blur、动态渐变或持续闪烁来表达“实时”。

### 2.4 图标、动效与反馈

- 图标使用 1.75px 线性图标，必须配合可读文字；状态不能只靠圆点颜色；
- 页面切换只使用 160–220ms 的 `opacity/transform`，列表数据更新不做全量 stagger；
- Confirm、Cancel、Accept、Complete、Retry 立即发起请求，按钮进入真实 `submitting/pending` 状态；动画不能延迟请求，也不能伪造成功；
- `prefers-reduced-motion` 或小程序系统减弱动效设置开启后，保留状态变化但移除位移动画；
- 同步状态使用“状态轨 + 文案 + 最后更新时间”，不使用无限转圈掩盖未知状态。

### 3.2 角色与任务 Scope

首期角色映射暂按以下规则执行：

| 业务称呼 | 系统角色 | 可见任务范围 | 管理端能力 |
|---|---|---|---|
| 主任 | `manager` | 全部团队、全部区域、全部任务状态 | 查看全部任务并进入全部管理模块 |
| 队长 | `leader` | 按所属团队/区域自动获得的任务 | 查看本人 Scope 内任务，不展示或返回其他 Scope 任务 |
| 员工 | `staff` | 分配给本人的 Edge Projection | 只操作本人任务，不进入管理端 |
| 系统管理员 | `admin` | 管理权限由系统 Scope 决定；默认可审计全局 | 用户、角色、Scope、系统配置和审计 |

队长不通过前端本地筛选获得权限。Core 必须依据队长所属团队/区域返回任务，任务详情也必须执行同样的 Scope 校验。主任的“全部任务”包括所有队长、团队、区域和状态。若用户知道无权任务 ID，详情页展示 403；若当前 Scope 没有任务，展示“当前管辖范围暂无任务”，不能显示成系统故障。

### 3.3 外壳导航

管理端使用左侧分组导航 + 顶部上下文栏。首期完整显示运行总览、航班运行、任务中心、人员管理、规则配置、事件与通知、审计日志、报表统计和系统管理；尚无内容或 API 的模块使用清晰的空态，不删除导航，也不伪造数据。导航项按角色显示：主任可见全部业务模块，队长只显示与任务、航班和本人 Scope 相关的模块，系统管理仅向 `admin` 开放。

员工 Web 与员工小程序使用独立的员工外壳，入口为“我的任务、通知、异常、历史、账号”。任务详情从列表进入并提供返回出口；员工端不显示管理端导航，也不把 Core 模块名称暴露给员工。

管理端使用左侧窄导航 + 顶部上下文栏；首期只显示“任务工作台”，调试页通过开发标识进入。员工端不设置复杂 Tab：底部保留“我的任务”和“账号”两个入口，任务详情使用返回箭头，不做多层菜单。

## 4. 认证与绑定页面

### 4.1 管理端登录页

管理端登录页服务 Admin、Manager、Leader，视觉上比员工端更克制，避免把管理端误认为员工入口：

```text
┌────────────────────────────────────────┐
│ 航班保障协同 / 运行管理台                │
│                                        │
│ 管理员登录                               │
│ 账号                                    │
│ [ 请输入管理账号                    ]    │
│ 密码                                    │
│ [ 请输入密码                       ]    │
│                                        │
│ [进入运行台]                            │
│ 仅限授权管理人员使用                     │
└────────────────────────────────────────┘
```

- 管理端不展示个人微信/企业微信绑定按钮，不复用员工登录文案；
- 登录失败使用稳定、非泄露性的提示；无权限登录成功后进入 `forbidden` 页面，不把无权限伪装成空数据；
- 管理端会话只能访问 Core audience，员工 Edge Token 不能通过前端路由绕过边界；
- 桌面端使用左侧深色品牌区 + 右侧白色表单区，小屏降级为单列，不依赖装饰性图片。

### 4.2 员工登录页

单一目标是完成认证，不在首屏解释系统架构。

```text
┌──────────────────────────────┐
│  航班保障协同                  │
│  员工入口                      │
│                              │
│  工号                          │
│  [ 请输入工号              ]   │
│  密码                          │
│  [ 请输入密码              ]   │
│                              │
│  [ 登录 ]                      │
│                              │
│  已绑定入口可快捷登录           │
│  [个人微信]  [企业微信]         │
│  当前入口：个人微信             │
└──────────────────────────────┘
```

规则：

- 工号和密码是明确的首要入口；密码输入框默认不可见，提供显示/隐藏按钮；
- 小程序显示当前启动入口（个人微信/企业微信），但不把外部标识展示给用户；
- 已绑定快捷登录按钮只在对应 Adapter 可用时展示；无绑定时不展示假的扫码或授权按钮；
- 登录失败统一提示“工号或密码不正确”，不暴露工号是否存在；锁定、停用和服务不可用使用独立的可行动提示；
- 员工 Web 在小屏使用单列居中卡片，在桌面保留左侧 30% 的深色品牌区，但不放大幅插画。

### 4.3 首次绑定页

登录成功但当前入口未绑定时进入绑定引导。先显示当前入口，再让用户完成一次平台授权；绑定成功后可以选择“继续绑定另一入口”，但不强制用户当场绑定两次。

```text
┌──────────────────────────────┐
│  完成员工账号绑定              │
│  工号 E000123                 │
│  当前入口：个人微信             │
│                              │
│  绑定后可直接进入“我的任务”     │
│                              │
│  [绑定个人微信]                 │
│  [绑定企业微信]                 │
│                              │
│  授权失败？使用工号密码重试       │
└──────────────────────────────┘
```

- `binding_required` 只允许进入绑定页，不允许加载任务列表或显示 Accept/Complete；
- 绑定冲突显示“该微信已绑定其他员工账号，请联系管理员处理”，不提供自动迁移按钮；
- 绑定成功后显示“已绑定，可从此入口直接登录”，再提供“进入我的任务”和“绑定另一入口”两个动作；
- 绑定票据过期后回到登录页，不能让用户重复提交旧票据。

### 4.4 账号安全页

账号安全页使用事实性文案：

| 模块 | 内容 |
|---|---|
| 当前账号 | 工号、员工展示名、当前会话到期提示 |
| 已绑定入口 | 个人微信：已绑定；企业微信：未绑定/已绑定 |
| 入口操作 | 绑定未绑定入口；解绑/换绑需后端授权并明确风险 |
| 当前会话 | 当前设备、最近使用时间、退出当前会话 |

当前不设计管理员设备列表，除非后端提供设备会话查询合同。退出只撤销当前 `sid`，不能由前端声称撤销所有设备。

## 5. 管理端页面设计

### 5.1 任务工作台 `/tasks`

页面的单一工作目标是“在当前角色管辖范围内找出需要处理的任务并进入正确的下一步”。主任默认可以查看全部任务，队长默认只查看所属团队/区域任务；不通过前端本地过滤替代服务端 Scope。默认打开“待确认”和“进行中”，历史任务通过任务历史入口查看。

```text
┌──────────┬───────────────────────────────────────────────┐
│ 运行台    │ 任务工作台                         2026-09-01 │
│          ├───────────────────────────────────────────────┤
│ 任务工作台 │ [待确认 12] [已分配 8] [执行中 4] [已完成]       │
│          │ 航班/任务搜索 [________________]  Area [全部]     │
│          ├───────────────────────────────────────────────┤
│          │ 时间     航班       任务              状态  候选 │
│          │ 07:40   MU2156    客舱清洁 / A区     待确认  4  │
│          │ 08:15   CA1832    行李转运 / B区     已分配  —  │
│          │ 09:05   ZH9210    机坪引导 / C区     执行中  —  │
│          │                                               │
└──────────┴───────────────────────────────────────────────┘
```

列表上下文：

- 顶部明确显示当前角色和可见范围：主任显示“全部团队 · 全部区域”，队长显示所属团队和区域；
- 主任可按队长、团队、区域、航班、状态筛选；队长只能使用自己 Scope 内的筛选项；
- 任务行显示所属团队、区域和管辖队长，避免把“当前执行员工”误认为“任务管辖队长”；
- 访问无权任务详情显示 403，当前管辖范围没有任务显示专属空态。

桌面布局：

- 1280px 以上：12 列网格，左侧导航 208px，内容区采用筛选栏 + 任务表格；
- 1024–1279px：收窄导航，筛选项折叠为工具栏，候选数和次要时间信息降级；
- 小于 768px：不追求管理端完整移动体验，改为单列任务卡，保证可读和可返回；
- 表格行左侧使用状态轨，点击整行进入详情；不能只把小按钮做成唯一入口；
- 列表顶部展示“最后同步时间”，刷新按钮只触发公开业务读取，不触发内部同步。

空态与错误：

- 空态：“当前筛选下没有待处理任务” + “清除筛选”按钮；
- 403：“当前账号没有查看这组任务的权限” + 返回工作台；
- 409/版本过期：“任务已被其他人更新，已保留在当前页面” + “刷新任务”；
- 503：“任务服务暂时不可用” + request ID + “重新加载”。

### 5.2 任务详情 `/tasks/:taskPublicID`

详情页采用“事实先行、操作靠后”的纵向结构：

1. 顶部航班条带：航班显示号、计划时间、Area、Task 状态、最后更新时间；
2. 任务摘要：任务名称、触发来源、当前负责人或未分配；
3. Candidate 区：仅 `awaiting_confirmation` 展示候选比较；按后端顺序展示岗位、能力、计划时间和资格提示；
4. Assignment 区：已分配/执行中/已完成时展示当前分配和状态历史；
5. 底部操作区：Confirm、Cancel 或只读状态；危险操作必须二次确认；
6. 诊断区：开发环境折叠展示 request ID、trace ID、confirmation ID，不展示 Token。

```text
┌──────────────────────────────────────────────────┐
│ ← 任务详情                 07:40  MU2156   待确认 │
├──────────────────────────────────────────────────┤
│ 客舱清洁 · T2 / A区                 状态轨 amber  │
│ 计划开始 07:40        触发：航班到达               │
├──────────────────────────────────────────────────┤
│ 推荐人员（4）                                     │
│ ○ 张三   客舱岗位   能力匹配   07:30 可用   [选择] │
│ ○ 李四   客舱岗位   能力匹配   07:35 可用   [选择] │
├──────────────────────────────────────────────────┤
│ 状态时间线  任务生成 → 候选计算 → 等待确认          │
├──────────────────────────────────────────────────┤
│              [取消任务]       [确认分配]           │
└──────────────────────────────────────────────────┘
```

Confirm 弹窗必须写清楚将要发生的事实：“确认后将创建 Assignment，并把任务发送到员工端”；提交时带 `candidate_public_id`、`confirmation_id`、`expected_task_version`。返回 202 或待同步结果不能在管理端直接写成已分配，当前 Core Confirm 的最终结果以服务端响应为准。

Cancel 弹窗必须要求原因。对于已被员工接受的任务，按钮显示后端允许的取消语义；不在前端自行判断是否可取消。

### 5.3 开发诊断 `/settings/diagnostics`

该页面仅在 `VITE_ENABLE_DEV_ACTOR` 等开发开关明确开启时注册，不进入生产菜单。内容只包括当前环境、Core/Edge 请求地址是否配置、最近一次 request ID/trace ID、Mock 场景和同步提示；不显示密码、Token、内部密钥或直接操作 Outbox/Inbox 的按钮。

## 6. 员工端页面设计

### 6.1 我的任务 `/tasks`

员工打开后的第一屏只有三件事：当前账号、同步状态、我现在要做的任务。列表按计划时间排序，当前可执行任务在首位；通知、异常、历史和账号通过员工端独立入口进入，不与管理端工作区混用。

```text
┌──────────────────────────────┐
│ 我的任务          个人微信 · 已登录 │
│ 今天 09 月 01 日               │
│ 已同步 07:42 · 刷新             │
├──────────────────────────────┤
│ 进行中 1   待接受 2   已完成 3    │
├──────────────────────────────┤
│ 07:40  MU2156                 │
│ 客舱清洁                         │
│ T2 / A区              待接受    │
│                          ›     │
├──────────────────────────────┤
│ 08:15  CA1832                 │
│ 行李转运                         │
│ T1 / B区              进行中    │
│                          ›     │
├──────────────────────────────┤
│ 我的任务                  账号 │
└──────────────────────────────┘
```

- 小程序使用安全区内边距，底部不放遮挡内容的悬浮按钮；
- 列表卡片整个可点击，按钮只在详情页出现，降低误操作；
- “已同步”是读取到的服务端时间，不承诺 Core 实时；发生 Projection 延迟时显示“正在同步，最后更新 xx:xx”；
- 空态：“今天还没有分配给你的任务”；若身份已认证但无数据，不显示错误红色；
- `identity_unmapped`、`staff_inactive`、`session_expired` 直接进入对应的认证/绑定引导，不渲染空任务页混淆用户。

### 6.2 任务详情 `/tasks/:taskPublicID`

详情页采用单列、44px 以上触控目标和底部固定主操作区：

```text
┌──────────────────────────────┐
│ ← 任务详情       待接受        │
├──────────────────────────────┤
│ 07:40  MU2156                 │
│ 客舱清洁                         │
│ T2 / A区 · 计划 07:40           │
├──────────────────────────────┤
│ 任务说明                         │
│ 完成客舱清洁并反馈异常情况         │
├──────────────────────────────┤
│ 当前状态                         │
│ 待接受 · 已同步 07:42             │
├──────────────────────────────┤
│ [接受任务]                       │
└──────────────────────────────┘
```

动作映射：

| 业务状态 | 主操作文案 | 提交后显示 |
|---|---|---|
| `assigned` | 接受任务 | 已提交，等待同步 |
| `in_progress` | 标记完成 | 已提交，等待同步 |
| `completed` | 无 | 已完成，只读 |
| `cancelled` | 无 | 任务已取消，只读 |

提交后：

- 立即禁用当前按钮，显示 `pending`；
- Edge 返回 202 时显示“操作已提交，等待任务状态同步”，而不是“操作成功”；
- 读到对应 Projection 后显示“已同步”；
- 网络超时显示“未确认是否提交成功”，默认不自动重发，提供“查看任务状态”和“返回列表”；
- 明确失败显示原因和“重新读取任务”，只有后端明确支持同一幂等键时才展示重试；
- 页面刷新后如果没有可查询的 Command 状态，只显示“等待同步/请重新打开任务”，不推测最终结果。

### 6.3 账号页 `/account`

账号页只提供身份和会话管理，不放任务统计：

```text
当前账号  E000123  张三
当前入口  企业微信 · 已绑定

身份入口
  个人微信   未绑定       [绑定]
  企业微信   已绑定

会话
  本次登录：今天 07:38
  [退出当前登录]
```

绑定另一个入口从这里开始，再进入绑定页。退出后清理本地短期凭据并回到登录页；不清理服务端业务数据、不删除任务 Projection。

## 7. 页面状态矩阵

### 7.1 认证状态

| 状态 | 页面表现 | 允许业务请求 |
|---|---|---|
| `unknown` | 显示轻量启动占位 | 否 |
| `authenticating` | 登录按钮进入处理中，表单不可重复提交 | 否 |
| `binding_required` | 显示绑定页和当前入口 | 否 |
| `authenticated` | 显示任务列表/管理工作台 | 是 |
| `expired` | 保留当前页面上下文，要求刷新或重新登录 | 否 |
| `forbidden` | 显示无权限说明和返回动作 | 否 |
| `unavailable` | 显示服务不可用、重试和 request ID | 否 |

### 7.2 业务状态与操作

业务状态由服务端数据决定，客户端只做展示和按钮可用性提示：

| 状态 | 管理端 | 员工端 | 状态轨 |
|---|---|---|---|
| `awaiting_confirmation` | 查看候选、确认/取消 | 不展示为可执行员工任务 | amber |
| `assigned` | 查看已分配 | 接受任务 | amber |
| `in_progress` | 查看执行中 | 标记完成 | info blue |
| `completed` | 只读 | 只读 | teal |
| `cancelled` | 只读、显示取消原因 | 只读、明确不可执行 | red |

### 7.3 命令显示状态

```text
idle → submitting → pending → syncing → confirmed
                                  └────→ failed
```

`pending`、`syncing` 是客户端显示层状态，不写回 Task；如果后端提供 Command 状态查询，再将 `failed` 与明确业务错误关联，否则保留“等待同步”而不自行判定。

## 8. 响应式与可访问性

### 8.1 Web 断点

| 断点 | 管理端 | 员工 Web |
|---|---|---|
| 360–767px | 单列降级，只保证可读和可返回 | 主设计尺寸，单列任务卡和底部操作 |
| 768–1023px | 紧凑工作台，筛选折叠 | 双栏详情可选，底部操作仍保留 |
| 1024–1279px | 收窄导航和表格列 | 桌面增强，任务列表/详情分栏 |
| ≥1280px | 完整工作台，12 列网格 | 桌面增强，不增加无关信息 |

小程序以 375px 设计稿和系统安全区为基线，所有页面适配 320–430px 常见宽度；不把 Web CSS 直接搬入小程序。

### 8.2 可访问性门槛

- 所有表单控件有可见标签，不依赖 placeholder 传达字段含义；
- 键盘可访问管理端导航、筛选、表格行、弹窗和主要按钮；
- 焦点环使用 2px `signal-amber` 外框，不能通过 `outline: none` 删除；
- 状态颜色同时显示文字/图标，错误、成功和待同步都有可读文本；
- 弹窗打开后焦点进入标题或第一个控件，关闭后回到触发按钮；
- 文字支持系统放大，员工端不能依赖固定高度裁切状态和错误信息；
- 动效遵守 reduced motion，网络等待期间仍保持明确的键盘/触控反馈。

## 9. F0 页面设计检查清单（待最终冻结）

以下内容已经根据当前讨论形成基线，但在正式 Mock v2 和视觉评审完成前不标记为最终冻结：

- 三端路由和外壳导航；
- 登录、首次绑定、账号安全、任务列表、任务详情和开发诊断页面；
- 主任 `manager` 查看全部任务，队长 `leader` 按团队/区域 Scope 查看任务，员工 `staff` 只查看本人任务，系统管理员 `admin` 负责系统管理；
- 管理端完整工作区导航：运行总览、航班运行、任务中心、人员管理、规则配置、事件与通知、审计日志、报表统计和系统管理；
- 管理端、员工 Web、员工小程序和各自登录页互相独立，探索预览的统一切换壳不属于正式产品；
- 员工端入口包含我的任务、通知、异常、历史和账号；
- 管理端桌面优先、员工端移动优先的布局规则；
- 航班条带、状态轨、颜色、字体、间距、圆角和动效限制；
- `loading/empty/error/forbidden/not_found/stale/version_conflict` 以及 `pending/syncing/confirmed/failed` 的展示方式；
- Confirm/Cancel/Accept/Complete 的文案、按钮状态和服务端事实边界；
- 个人微信、企业微信共用员工业务页面，身份差异只停留在认证 Adapter 和入口上下文；
- 页面不依赖 Core/Edge 内部同步接口，不把本地缓存当作业务事实。

以下事项仍需最终评审：任务是仅按团队/区域获得还是同时需要显式队长字段、Scope 交叉时的合并规则、无权/无数据的完整交互、管理端首期每个模块的真实业务字段，以及视觉方向和美化细节。真实微信/企业微信配置、生产密钥和域名、前端工具链、Mock fixture、客户端 Command 幂等键和公共 Command 状态查询、在线 Docker/MySQL 联调仍是工程 F0/F1 门槛。
