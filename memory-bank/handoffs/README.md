# 任务交接文件说明

本目录保存按任务范围拆分的“当前交接快照”。它们不是无限增长的日志；每个文件只保留对应范围的最新状态、真实验证结果、阻塞项和下一步。

## 文件分工

| 文件 | 负责范围 |
|---|---|
| `frontend.md` | `frontend/` 下的管理端、员工小程序、员工 Web、共享包、前端工具链和前端性能 |
| `backend.md` | `cmd/`、`internal/core`、`internal/edge`、`internal/integration`、API、业务 Migration 和后端性能 |
| `infrastructure.md` | Docker、Compose、Core/Edge MySQL、Redis、部署、环境、同步运行保障和基础设施性能 |

如果一个任务同时跨越多个范围，分别更新涉及的任务文件；不要把三个范围的详细内容重新堆回根 `HANDOFF.md`。

## 更新规则

- `HANDOFF.md` 只保存项目级摘要、当前任务文件索引和跨任务冲突；历史章节只作为旧证据，不作为当前状态的唯一来源。
- 任务文件采用滚动快照：更新时替换过期的“当前状态”，不无限追加重复内容。
- `memory-bank/progress.md` 继续按时间追加里程碑、测试结果和临时阻塞；过长后按阶段归档。
- `memory-bank/project-memory.md` 只保存长期有效的架构和协作规则，不保存某次任务的临时细节。
- 交接内容必须区分“已实现”“已验证”“设计中”“待确认”和“阻塞”，不能把计划写成实现。
- 测试、构建、Docker、数据库和 Compose 结果必须以本次真实命令输出为准；未运行的检查标记为“未运行”。

## 并行会话规则

- 同时读取文件不会产生冲突；同时写同一个交接文件可能产生覆盖或交错内容。
- 写入前必须重新读取目标任务文件、根 `HANDOFF.md` 的当前索引和 `git diff`；如果发现其他会话已经修改，先合并事实再写入，不覆盖未知修改。
- 结束会话的触发语义包括“我要结束当前这个对话了”“我要退出当前对话”“准备开新线程”及明确表达结束当前工作会话的同义说法；普通的“退出页面/退出程序”不触发交接。
- 触发后先更新本次任务对应的文件，再更新根 `HANDOFF.md` 摘要；如果没有明确任务范围，写入根文件的“待确认/跨范围”部分，不擅自覆盖其他任务快照。
